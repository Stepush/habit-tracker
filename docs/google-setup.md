# Google-вход и Google Sheets

Один личный Google-аккаунт, один приватный файл таблицы, отдельные листы `YYYY-MM`.
Google Cloud нужен для настройки API; отдельная база и Clerk не используются.
Оплату подключать не требуется для стандартного использования в пределах квот Sheets API.

## 1. Проект и таблица

1. Создайте проект `Ritm Habit Tracker` в <https://console.cloud.google.com/>.
2. `APIs & Services → Library → Google Sheets API → Enable`.
3. Создайте пустую Google-таблицу `Ритм` в своём Google Drive. Оставьте общий доступ `Restricted`.
4. В адресе `https://docs.google.com/spreadsheets/d/ID/edit` скопируйте `ID`.
5. Не создавайте месячные листы вручную: приложение создаёт их при сохранении. Начальный пустой «Лист1» можно оставить.

## 2. Сервисный аккаунт для таблицы

1. `IAM & Admin → Service Accounts → Create service account`.
2. Название `ritm-sheets`. Роли проекта и domain-wide delegation не нужны: оставьте эти шаги пустыми.
3. Откройте созданный аккаунт → `Keys → Add key → Create new key → JSON`.
4. Сохраните скачанный JSON вне папки проекта. Не отправляйте его в чат или GitHub.
5. Скопируйте `client_email` и `private_key` из этого файла в локальный `.env.local` (см. ниже).
6. В таблице нажмите «Настройки доступа» и добавьте `client_email` как редактора. Не включайте публичный доступ.

Сервисный аккаунт имеет доступ только к файлам, которыми с ним поделились. Вход пользователя и технический доступ к таблице — разные механизмы.

## 3. Google-вход

1. В проекте откройте `Google Auth Platform` (в старом интерфейсе — `APIs & Services → OAuth consent screen`).
2. Нажмите `Get started`, укажите имя `Ритм`, email поддержки и контактный email.
3. Для личного Gmail выберите аудиторию `External`. В режиме Testing добавьте свой email в `Audience → Test users`.
4. В `Clients → Create client` выберите `Web application`.
5. В `Authorized redirect URIs` добавьте ровно:

   ```text
   http://127.0.0.1:3000/api/auth/callback
   ```

6. Сохраните Client ID и Client secret в `.env.local`. Для серверного OAuth-потока JavaScript origins не требуются.
7. Используем только `openid email profile`. Разрешение на все ваши таблицы в пользовательском входе не запрашивается. Refresh tokens не храним.

## 4. Локальные настройки

Скопируйте `.env.example` в `.env.local`. Файл `.env.local` исключён из Git.

```dotenv
APP_URL=http://127.0.0.1:3000
SESSION_SECRET=<случайная строка минимум 32 символа>
GOOGLE_CLIENT_ID=<OAuth Client ID>
GOOGLE_CLIENT_SECRET=<OAuth Client secret>
GOOGLE_OWNER_SUB=0
GOOGLE_SERVICE_ACCOUNT_EMAIL=<client_email из JSON>
GOOGLE_PRIVATE_KEY="<private_key из JSON с буквальными последовательностями \n>"
GOOGLE_SPREADSHEET_ID=<ID таблицы>
```

Получить SESSION_SECRET можно командой `openssl rand -hex 32`. Не используйте пример вместо случайного секрета.

Вместо ручного копирования секретов можно скачать JSON OAuth-клиента из `Google Auth Platform → Clients` и создать `.env.local` локальной командой:

```sh
npm run setup:google -- --service-account /абсолютный/путь/service-account.json --oauth-client /абсолютный/путь/oauth-client.json --spreadsheet https://docs.google.com/spreadsheets/d/ID/edit
```

Скрипт читает только указанные локальные файлы, генерирует случайный SESSION_SECRET, создаёт `.env.local` с правами 600, не выводит секреты и отказывается затирать существующую конфигурацию. Файлы с пробелами в пути заключайте в кавычки.

При копировании private_key сохраняйте `-----BEGIN PRIVATE KEY-----`, `-----END PRIVATE KEY-----` и переносы `\n`. Не вставляйте весь JSON в эту переменную.

### Привязка владельца

1. Перезапустите `npm run dev`, откройте **именно** <http://127.0.0.1:3000>.
2. Нажмите «Войти через Google» и выберите свой аккаунт.
3. Пока `GOOGLE_OWNER_SUB=0`, доступ закрыт для всех. После проверки Google покажется JSON с вашим `googleSubject` и email.
4. Скопируйте `googleSubject` в `GOOGLE_OWNER_SUB`, перезапустите сервер и войдите заново.

Для привязки без ручного редактирования файла можно выполнить `npm run setup:google -- --owner-sub ВАШ_GOOGLE_ID`.

Этот идентификатор постоянный для Google-аккаунта: изменение имени, пароля или email внутри того же аккаунта не отвязывает историю. Другой Google-аккаунт будет отклонён.

### Другой аккаунт без изменения кода

Для смены владельца установите `GOOGLE_OWNER_SUB=0`, войдите новым аккаунтом и повторите привязку. Старые сеансы перестают проходить проверку после применения новой конфигурации. Меняется настройка, код не редактируется. На Vercel после изменения переменных требуется redeploy. Доступ к самой таблице Google Drive управляется отдельно её владельцем.

## 5. Перенос старых данных

Локальные записи не загружаются в облако автоматически и не затираются облачной историей.

1. До настройки `.env.local` в старом локальном режиме экспортируйте все месяцы в JSON.
2. Если Google уже настроен, для экспорта можно временно убрать `.env.local` из папки проекта и перезапустить dev-сервер. Откройте тот же браузер и адрес, где были сохранены данные.
3. Верните конфигурацию, перезапустите сервер, войдите через Google.
4. В разделе «Резервная копия» импортируйте JSON. Импорт явно подтверждает замену совпадающих месяцев и записывает все выбранные месяцы в Google одним атомарным batchUpdate.
5. Обновите страницу и проверьте историю. Оставьте JSON-копию у себя.

## 6. Структура таблицы

Каждый лист `YYYY-MM` содержит заголовок и до 10 привычек. Колонки: ID, название, цвет, короткое название, дни 1–31, время сохранения и маркер формата. Значения дней — числа `0` и `1`; несуществующие дни пустые.

Названия, порядок и ID привычек сохраняются снимком для каждого месяца. Текст записывается как строка, даже если начинается с `=`: формулы из названий не выполняются. Удалённые привычки очищаются при следующем сохранении. Приложение не меняет посторонние листы.

Не переименовывайте месячные листы и служебные заголовки. Для исправления отметок вручную используйте только числа 0/1. Произвольное повреждение структуры приводит к явной ошибке загрузки, а не к замене истории пустыми данными.

## 7. Что проверяем перед публикацией

- Владелец входит, чужой Google-аккаунт получает отказ; без сессии `/api/months` возвращает 401, включая `/poc` за тем же входом.
- Сохранение создаёт лист, повторное сохранение обновляет его без дублей.
- Удаление привычки очищает её старую строку; короткие месяцы имеют пустые несуществующие дни.
- После перезагрузки и на втором устройстве история совпадает.
- При сбое сети или истечении сессии интерфейс не сообщает об успешном сохранении. Черновик остаётся для JSON-экспорта.
- Экспорт/импорт нескольких месяцев, включая старый формат, работает.
- Выход удаляет cookie; перезагрузка возвращает к входу.

Перед сохранением сервер сравнивает версию месяца с загруженной клиентом. Это обнаруживает уже завершённые изменения на другом устройстве или в самой таблице. Google Sheets не предоставляет compare-and-swap для такого обновления: два запроса, пришедшие строго одновременно, могут пройти проверку и последний перезапишет первый. Для одного пользователя избегайте одновременного сохранения с нескольких устройств. Атомарность batchUpdate защищает от частичного импорта, но не решает эту гонку.

Сбой связи после принятия записи Google может дать неопределённый результат: экспортируйте черновик и перезагрузите историю перед повтором. Автоматического повтора записи нет.

## 8. Vercel

1. Подключите GitHub-репозиторий к Vercel.
2. Добавьте все переменные из `.env.local` в настройки **Production**. APP_URL замените на постоянный HTTPS-адрес сайта без завершающего слеша.
3. В OAuth-клиент добавьте `<APP_URL>/api/auth/callback` в Authorized redirect URIs.
4. Секреты не должны иметь префикс `NEXT_PUBLIC_`. В Vercel значение GOOGLE_PRIVATE_KEY вводится без внешних кавычек, с реальными переносами или `\n`.
5. Пересоберите deployment и пройдите проверки выше. Preview-публикации лучше не подключать к рабочей таблице.

В production приложение **не открывает локальный режим**, если конфигурации нет или она неполная. Сессия подписана HMAC, живёт 7 дней, cookie HttpOnly/SameSite=Lax и Secure на HTTPS. Изменяющие запросы требуют совпадения Origin. OAuth использует state, nonce и PKCE. Токены Google не сохраняются в браузере.

В dev без единой переменной Google доступен прежний локальный режим. Частично заданная конфигурация показывает экран настройки. Фото по-прежнему обрабатываются в браузере и не отправляются в Google.
